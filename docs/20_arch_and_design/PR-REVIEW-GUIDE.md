# LLMTier PR Review Guide

## 审查原则

**先理解设计意图，再审查实现。**

代码审查不是找语法错误，是验证"这个实现是否正确反映了设计意图"。

---

## 必读文档

审查前必须读：

1. **`docs/20_arch_and_design/README.md`** — LLMTier 是什么、谁用、怎么用
2. **`docs/70_verification/plans/llmtier-v0.3-test-plan.md` §2.2** — 测试环境约束
3. **本次改动的相关设计文档** — 了解这次改了什么、为什么改

---

## 架构层面检查项

### 1. 测试是否反映真实使用场景

LLMTier 运行在局域网（`192.168.1.x`），consumer 在同一 LAN 上调用它。

**检查问题**：
- 测试里的 endpoint 配置，在真实环境中存在吗？
- 测试用 LAN IP 还是 localhost？真实场景是 LAN 调用。
- provider 指向的端口和模型，和实际部署环境一致吗？

**常见错误模式**：
- 测试用 `127.0.0.1` 或 `localhost`，但真实环境不是这样
- 端口写错（如 9100 vs 9000）
- 模型名称写错（如 bge-m3 vs Qwen3-Embedding）

### 2. 测试依赖是否写清

测试依赖外部服务时，必须在文件头部写明：
- 依赖哪个环境的什么服务
- 服务地址和端口
- 使用的模型名称

**检查问题**：
- reviewer 看完测试文件，能判断依赖是否合理吗？
- 如果依赖的服务不可用，测试会 skip 还是 fail？

### 3. 测试设计是否合理

**检查问题**：
- 测试是否覆盖了关键路径和错误路径？
- 测试是否有副作用？（修改了共享状态）
- 测试失败时，错误信息是否足够定位问题？

---

## 常规检查项

- [ ] 功能逻辑正确
- [ ] 测试覆盖正确
- [ ] 没有硬编码敏感信息
- [ ] 单元测试通过
- [ ] 系统测试通过

---

## 常见问题检查清单

| 问题 | 为什么是问题 | 如何检查 |
|------|-------------|----------|
| 测试用 localhost | 真实场景是 LAN 调用 | 看 endpoint 配置是否含 192.168.1.x |
| 端口写错 | 服务实际不在那个端口 | 对照测试计划 §2.2 |
| 模型名称写错 | 模型可能不存在 | 查 OMLX /v1/models |
| 依赖没写清 | reviewer 无法判断合理性 | 看文件头部是否有依赖说明 |
| 测试有副作用 | 污染环境，影响其他测试 | 检查是否用临时目录和端口 |
