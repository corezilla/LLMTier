## 3. 通用规则与经典示例：宽表 → 固定格式段落（适用于所有 STD 模板）

### 3.1 规则

**任何 STD 模板**中，若某个表格**宽度不足**（列多、或单元格内容长、在 Markdown 中折行严重），**作者可以选择**改用"**固定格式段落**"逐条描述，而非强行使用表格。此规则**不局限于模块设计模板**，建议写入 STD 通用写作指南（`design-writing-guide` / `ai-authoring-guide`），对所有模板生效。

- **不是**取消表格：**矩阵型**（≤3–4 列、单元格短、行间可比）仍用表格；**记录型**（每行是一组多字段的独立记录，如功能/测试/失败/机制承接/接口/实现步骤）改段落。
- **判定参考**：列数 ≥ 6，或单元格平均长度较大（长句/代码/路径），或同一行字段之间**无横向对比需求**。
- **表达形式**：`#### <ID> · <名称>` + 固定字段的 `- **字段**：值` 列表；字段名与顺序由各模板统一规定。
- **好处**：不受列宽限制、字段名可读、便于 diff 与机器/AI 解析、可容纳完整路径/签名/错误码。
- **一致性要求**：同一模板内**同一类记录**用同一种表达（要么全表、要么全段落）；跨模板的同类记录（如"机制承接/接口/失败项"）建议统一字段名。

### 3.2 经典示例（需求/功能记录表，7 列 → 段落）

**改写前（表格，7 列，Markdown 中明显折行、难读）：**

```text
| Function ID | 调用方 | 输入 | 行为 | 输出 | 错误 | 验收条件 |
|---|---|---|---|---|---|---|
| F-API-AUTH | 全部 | Authorization/客户端地址/端点 | 按端点选 data/admin 角色，免登录或 Bearer 判定，产出 Principal | Principal | 503 auth_not_configured / 401 / 403 | 端点→角色映射正确；下游不二次校验 |
```

**改写后（固定格式段落）：**

```text
### 2.3 F-API-AUTH · 访问信任判定
- **调用方**：全部
- **输入**：`Authorization` / 客户端地址 / 端点
- **行为**：按端点选 `data`/`admin` 角色；免登录或 Bearer 判定，产出 `Principal`
- **输出**：`Principal`
- **错误**：503 `auth_not_configured` / 401 / 403
- **验收**：端点→角色映射正确；下游不二次校验（C-TRUST-1）
```

同一规则也可用于更宽的表（机制承接表 8 列）：

```text
#### A.2 `llmtier-inference-stream-mechanism` / R-INF-01 · 推理与流式返回
- **来源 Capability / Step / Constraint / 接口成员**：C-INFER-1/2、Step 8
- **本模块必须负责的行为与保证**：SSE 帧序、terminal 唯一、`request_id` 透传、请求体上限
- **本模块提供 / 消费的接口**：`response_stream`、`/v1/responses` 路由
- **本文落实位置**：§7、§8、§12
- **代码文件 / symbol**：`app.py` + `sse.py`
- **允许自行决定的范围**：缓冲/传输实现
- **本地验证 / 组合验证交接**：契约；组合（Piko 联调）
```

**LLMTier 实证**：M001/M002 模块设计中，§1.1 使用场景、§2 功能、§3 操作面、§4 外部边界、§5 内部组件/文件间接口、§6 数据模型/数据结构、§7 流程/步骤、§10 失败、§12 容量、§13 文件分解/实现步骤、§14 测试、§15 未决、附录 A 机制承接表——**共 14 类记录表**均以固定格式段落表达；现仅保留 2–4 列的短表（封面、摘要、页面文件划分、图标）。

## 4. 经验：模块设计应显式要求的四类内部细节

按 `design.definition` 2.3.0 实际写作时，以下四类内容对"分解到代码"最关键，**建议模板显式要求**：

1. **内部相互调用过程**：文件→文件调用链（谁调谁、传什么、失败怎么走）。
2. **文件与文件之间的接口**：文件/符号 + 签名 + 输入 + 输出/异常（LLMTier 记为 `IF-n` 条目）。
3. **数据结构**：字段级（dataclass/字段/单位/寿命/归属）。
4. **设计→代码文件分解**：文件 → 职责 → 关键 symbol → 实现状态。

## 5. 验收 Gate

1. **G1**：§3 支持"服务端点型操作面"表达，且保留无 UI/CLI 的 N/A 路径。
2. **G2**：§2、附录 A 可用**固定字段段落**表达；且"宽表可选段落式"作为**通用规则写入 STD 写作指南，对所有模板生效**（见 §3）。
3. **G3**：§5/§6/§7/§13 显式要求"内部调用过程 / 文件间接口 / 数据结构 / 文件分解"。
4. **G4**：一份真实模块设计可不依赖外部约定完成"设计→代码文件"追溯。
